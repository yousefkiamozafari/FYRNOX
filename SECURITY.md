# Security Policy & Vulnerability Disclosure

## Supported Versions

Only the latest release receives active security patches. We recommend all users stay updated with the latest release.

| Version | Supported          |
| :------ | :----------------- |
| 1.0.x   | :white_check_mark: |
| < 1.0.0 | :x:                |

---

## Reporting a Vulnerability

The FYRNOX project takes the security of its users and infrastructure seriously. If you discover a security vulnerability, please report it responsibly so that we can resolve it before public disclosure.

### How to Report

1. **GitHub Security Advisory (Preferred):**  
   Submit a confidential advisory directly via GitHub at [https://github.com/yousefkiamozafari/FYRNOX/security/advisories/new](https://github.com/yousefkiamozafari/FYRNOX/security/advisories/new).

2. **Direct Maintainer Contact:**  
   If you cannot use GitHub Advisories, email the project maintainer:
   - **Maintainer:** Yousef Kia
   - **Email:** `yousefkiamozafari@gmail.com`
   - **Subject:** `[SECURITY] FYRNOX Vulnerability Report`

**Please do NOT open public GitHub Issues for undisclosed security vulnerabilities.**

### Information to Include in Your Report

To help us triage and resolve the issue quickly, please provide:
* Description of the vulnerability and its potential impact.
* Exact version of FYRNOX affected (e.g. `v1.0.4`).
* Operating system details (e.g. Windows 11 x64, Windows 10 x86).
* Detailed reproduction steps or a minimal proof-of-concept (PoC).
* Any proposed mitigations or code patches.

---

## Response & Disclosure Process

1. **Acknowledgment:** We will acknowledge receipt of your vulnerability report within **48 hours**.
2. **Investigation & Triage:** We will verify the issue and assess its severity.
3. **Patch Development:** A fix will be developed and tested privately on a security branch.
4. **Release & Credit:** A patch release will be published, and you will be credited in the release notes (unless you request anonymity).
